숫자 발굴 — 수업용 연산 게임

보드게임 파라오코드의 규칙을 바탕으로 만든 웹 연산 게임입니다. 주사위 세 개의 수를 모두 써서 피라미드에 깔린 블럭의 수를 만들고, 만든 블럭을 가져가 점수를 쌓습니다. 서버 없이 HTML 파일 하나로 돌아가며, 시드를 공유하면 반 전체가 같은 문제로 겨룰 수 있습니다.

파일 구성
파일	용도
pyramid-dig-plus.html	메인 게임. 사칙연산/확장 규칙, 식 만들기/풀이 보기 모드, 타이머, 시드, 점수 제출, 교사 순위표까지 전부 포함

게임 규칙
판

블럭 15개가 5줄 피라미드로 깔립니다. 위에서부터 1·2·3·4·5개.

            [ 88 ]              1줄 최상급  70~96   15~26점
         [ 46 ] [ 58 ]          2줄 상급    46~69    8~14점
      [ 45 ] [ 44 ] [ 34 ]      3줄 중급    31~45    5~8점
   [ 27 ] [ 28 ] [ 14 ] [ 21 ]  4줄 하급    13~30    3~5점
[ 4 ] [ 3 ] [ 9 ] [ 7 ] [ 10 ]  5줄 기본     1~12    1~3점
줄마다 숫자 크기 범위가 정해져 있어 위로 갈수록 큰 수가 깔립니다
같은 줄 안에서는 만드는 방법이 드문 수일수록 점수가 높습니다
한 판에 같은 숫자는 두 번 나오지 않습니다
20보다 큰 소수(73, 89, 101 …)는 후보에서 제외했습니다. 곱셈으로 접근할 길이 없어 암산이 가혹하기 때문입니다
주사위

6면 주사위 3개. 세 수를 전부 한 번씩 써야 합니다. 남기거나 두 번 쓸 수 없습니다.

연산

사칙연산 모드 — + − × ÷ 네 가지만

확장 모드 — 여기에 네 가지 추가

연산	조건	예
n! 팩토리얼	3~6에만 (1!, 2!는 자기 자신이라 제외, 7! 이상은 너무 커서 제외)	4! = 24
√ 루트	제곱수에만 (결과가 정수)	√36 = 6, √2 는 불가
nCr 조합	n ≥ r ≥ 0, n ≤ 20	6C2 = 15
n² n³ 거듭제곱	지수는 2 또는 3만	5² = 25, 6⁶ 은 불가

공통 제약

나눗셈은 나누어떨어질 때만. 중간 계산도 정수여야 합니다 (6 ÷ (2×2) 는 1.5라 불가)
중간값이 음수인 것은 허용
모든 값은 절댓값 2000 이하
단항 연산(! √)은 주사위 하나에도, 중간 결과에도 붙일 수 있고 최대 두 번까지 연달아 가능 (√36 → 6 → 6!)

예시

주사위 6, 2, 2 → 12      (6 − 2)! ÷ 2 = 12
주사위 2, 1, 5 → 25      2 × 1 = 2,  5² = 25
주사위 5, 6, 6 → 14      5! = 120,  120 ÷ 6 = 20,  20 − 6 = 14
진행
주사위를 굴립니다
만들 수 있는 블럭을 가져갑니다 (여러 개 가능)
가져간 자리에 같은 줄의 새 블럭이 채워집니다
더 만들 게 없으면 다시 굴리기
시간이 끝나거나 블럭이 다 떨어지면 종료

줄마다 게임 전체에서 쓸 수 있는 블럭 수가 정해져 있습니다: 4 · 7 · 9 · 10 · 10장 (총 40장). 초기 판 15장을 빼면 보충용은 25장. 덱이 떨어진 자리는 점선 빈칸으로 남습니다.

두 가지 모드

식 만들기 (기본, 경쟁용) 블럭을 고르면 주사위 세 수가 칩으로 뜹니다. 칩 → 연산 → 칩 순서로 누르면 합쳐지고, 결과가 첫 수 자리에 남으면서 다음 식의 첫 수로 자동 선택됩니다. 칩이 하나 남았을 때 목표와 같으면 획득. 틀리면 되돌리기로 다시 조립합니다. 앱은 검증만 하고 풀이는 학생이 만듭니다. 찍기가 불가능합니다.

풀이 보기 (연습용) 블럭을 누르면 풀이 과정이 단계별로 뜹니다. 만들 수 없는 블럭을 누르면 −2점에 3초 쿨다운. 15칸 중 평균 9칸이 정답이라 찍기만 해도 점수가 나오므로 경쟁에는 쓰지 마세요. 규칙 익히기용입니다.

시드 (문제 번호)

같은 시드를 넣으면 판 배치, 블럭 점수, 주사위 순서가 전원 동일해집니다. 운이 개입하지 않아 순수 실력 비교가 됩니다. 비워두면 네 자리 번호가 무작위로 정해지고 화면 상단 "문제" 칸에 표시되므로, 나중에 같은 번호로 다시 풀 수 있습니다.

시드마다 편차가 있습니다. 어떤 시드는 윗줄이 처음 몇 굴림에서 전혀 안 열리기도 합니다. 수업 전에 쓸 시드를 한 번 돌려보고 고르는 것을 권합니다.

전체의 몇 %

비교 대상은 가상 플레이어 3000~4000명의 시뮬레이션 점수 분포입니다. 탐색 속도, 정확도, 고득점 블럭을 노리는 정도를 각각 다르게 준 플레이어로 실제 게임 규칙을 돌려 뽑았습니다. 규칙 × 모드 × 시간 = 12개 표가 파일 안에 들어 있어 서버 없이도 계산됩니다.

연산 내역

식 만들기 모드에서는 학생이 실제로 쓴 연산을 셉니다. 사칙연산만 썼으면 기초, 팩토리얼만 더 썼으면 팩토리얼, 두 종류 이상 섞었으면 복합. 풀이 보기 모드에서는 "그 블럭을 푸는 데 최소한 필요했던 연산"으로 추정합니다.

같은 점수여도 "기초 10개"와 "복합 3개"는 성격이 다릅니다. 이 차이를 짚어주기 좋습니다.

멀티플레이

각자 자기 판을 풀기 때문에 실시간 동기화가 필요 없습니다. 시드로 공정성을 확보하고, 점수만 모으면 됩니다.

서버 없이

결과창의 결과 복사 버튼을 누르면 이름 · 점수 · 발굴 수 · 문제 번호 한 줄이 복사됩니다. 구글 폼이나 채팅에 붙이게 하세요. 코드 수정 없이 오늘 바로 쓸 수 있습니다.

학생은 결과창의 점수 제출 버튼으로 전송
교사는 주소 뒤에 ?teacher=1 을 붙여 열고, 시드를 넣고 순위 보기 — 5초마다 갱신되며 이름·점수·발굴 수·연산 내역이 표시됩니다

주의: anon key는 HTML에 그대로 노출됩니다. SQL에서 insert/select만 허용하고 수정·삭제는 막았지만, 학생이 개발자도구로 가짜 점수를 넣는 것까지 막지는 못합니다. 수업용으로는 충분하나 상품이 걸린 대회라면 교사가 화면을 확인하는 절차를 두세요.

주사위를 8면으로 올리면 도달 가능한 값이 넓어져 윗줄이 더 자주 열립니다. 다만 백분위 표는 6면 기준이라 SIDES 를 바꾸면 "전체의 몇 %"는 맞지 않게 됩니다.

등급 후보는 시작할 때 216가지 굴림을 전부 계산해 자동으로 만들어집니다 (약 0.1초). band 나 연산 규칙을 바꾸면 후보도 자동으로 따라옵니다.

Streamlit 버전 (pharaoh_app.py)

HTML 버전과 다른 턴제 규칙입니다. 교사가 주사위를 굴리면 전원이 같은 판에서 블럭을 하나 고르고, 턴 종료 시 일괄 채점합니다. 같은 블럭을 여러 명이 고르면 점수를 나눠 갖기 때문에 "남들이 안 볼 어려운 블럭"을 노리는 전략이 생깁니다.

pip install -r requirements.txt
streamlit run pharaoh_app.py

사이드바에서 교사/학생 화면을 고릅니다. 방은 하나뿐이고 상태는 메모리에 있어 서버가 재시작되면 초기화됩니다. 사칙연산만 지원하며 식 만들기 모드는 없습니다. 실시간 폴링 대신 턴 단위로 집계하므로 Streamlit의 재실행 구조와 잘 맞습니다.

Community Cloud에 올릴 때는 pharaoh_app.py 와 requirements.txt 를 저장소 루트에 두면 됩니다. 12시간 트래픽이 없으면 앱이 잠드니 수업 직전에 한 번 열어 깨워두세요.

알려진 제한
백분위는 실제 학생 데이터가 아니라 시뮬레이션입니다. 반 분위기에 따라 체감이 다를 수 있습니다
식 만들기 모드에서 풀이 가능 여부를 미리 알려주지 않습니다. 학생이 고른 블럭이 그 주사위로 불가능할 수도 있고, 그것을 판단하는 것 자체가 게임의 일부입니다
사칙연산 모드의 1줄 후보는 72, 75, 80, 90, 96 다섯 개뿐이라 자주 반복됩니다. 한 게임에 4장만 쓰므로 실제로는 크게 거슬리지 않습니다
